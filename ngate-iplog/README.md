# ngate-iplog: какие команды выполняет ngatetun

Это диагностика перед переходом на схему с OpkgTun0. `ngatetun` настраивает tun-интерфейс,
вызывая `ip` (и `resolvconf` для DNS). Сначала он ищет их по `PATH`, где `/usr/local/sbin`
идёт первым. Обёртки в `/usr/local/sbin` записывают каждый вызов (аргументы, stdin, вывод,
код возврата) в `/var/log/ngate-iplog.log` и передают его настоящей утилите.

- `ip` — вызов передаётся настоящему `ip`, поведение не меняется.
- `resolvconf` — если настоящего нет, вызов только записывается и возвращается 0.
  Так видно, какие DNS-серверы и домены выдаёт шлюз. Без обёртки ngatetun просто
  пропускает настройку DNS, так что на работу туннеля это не влияет.
- `nmcli` — обёртка ставится, только если NetworkManager есть. На время теста
  `ignoreNetworkManager=1` всё равно переводит ngatetun на iproute2, как будет на роутере.

## Где запускать

Подойдёт любая Linux-машина с установленным клиентом NGate: chroot на роутере
или обычный ПК (amd64). Нужен root.

В chroot на роутере `S99debian` уже добавляет `/usr/local/sbin` в `PATH`.

## Порядок

```sh
sudo sh install.sh                 # обёртки + journalVerbose=5 + перезапуск ngatetun
# подключиться к NGate (консольный клиент или GUI), подождать ~1 минуту,
# открыть что-нибудь внутреннее, чтобы проверить работу туннеля
sudo sh collect.sh connected       # снимок: интерфейсы, маршруты, правила, tun-флаги
# отключиться от NGate
sudo sh collect.sh disconnected    # второй снимок + архив /tmp/ngate-diag.tgz
sudo sh install.sh remove          # убрать обёртки, вернуть service.ini
```

Прислать `/tmp/ngate-diag.tgz`. Перед отправкой его стоит просмотреть: там будут ваши
внутренние адреса, маршруты и, возможно, логин из журнала клиента. Пароль и OTP в эти
журналы не попадают.
